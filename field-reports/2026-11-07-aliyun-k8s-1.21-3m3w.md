## 4. 遇到的问题

### 4.1 worker2 `yum update`：`Protected multilib versions`，但没有 i686 包
- 原因：rpm 库里 6 组重复包（glibc-common、nss-softokn-freebl、tzdata、grub2-*、centos-release），旧事务中断留下的（运行 1712 天）。`package-cleanup --cleandupes` 因依赖删不掉。
- 处理：旧副本 `rpm -e --justdb --nodeps` → update → reinstall。
- 状态：promoted → `pitfalls.md` §2；`survey.sh` 报 HIGH

### 4.2 7→8 阻断 `Use of NFS detected`
- 原因：pod 的 NFS PVC 挂载在节点上；worker2/3 的 fstab 也有 NFS（含阿里云 NAS）。
- 处理：drain 后 `k8s.sh nfs-off`（注释 fstab 的 NFS + 卸载），EL10 后 `k8s.sh nfs-on`。
- 状态：promoted → `k8s.sh nfs-off/nfs-on`、`kubernetes.md`

### 4.3 ★ master1/master2 重启进 8→9 升级环境约 5 秒就 emergency，VNC 里敲不了命令
- 现象：`Entering emergency mode`；VNC 键盘输入无回显。
- 原因：
  1. 阿里云内核参数 `console=tty0 console=ttyS0`，emergency shell 开在串口，VNC 只能看。
  2. 串口日志（控制台"获取实例系统日志"）显示 `Dependency failed` ← `sysroot-sys-devices-…-net-eth0-speed.mount`：fstab 里有 `/home/admin/eth0-speed.mock /sys/class/net/eth0/speed none bind,nofail`（阿里云 OceanBase 镜像脚本 `set_ecs_special.sh` 写入，master3 没有）。leapp 把 fstab 固化成升级 initramfs 的 mount unit，`nofail` 也没用。
  3. 第一次只在 EL8 上注释了 fstab 就重启，还是 emergency——**升级 initramfs 是 `leapp upgrade` 时生成的，事后改 fstab 无效**，必须重新 `hop.sh up`。
- 回到旧内核：GRUB 超时 1 秒，控制台重启会断开 VNC，手动按键 / 普通自动化按键都赶不上；最终在 VNC 页面里用 JS 调 noVNC 的 `rfb.sendCtrlAltDel()` + `setInterval(rfb.sendKey(0xff52), 100)`，控制台强制重启时再用定时器自动点"连接远程连接"重连。
- 状态：promoted → `hop.sh up` 自动注释此类条目（EL10 post 恢复），`survey.sh` BLOCKER，`recovery.md` B2

### 4.4 切到 NetworkManager 后 NM 接管 cni0
- 处理：`k8s.sh nm`（unmanaged-devices）。状态：promoted → `k8s.sh`

### 4.5 worker2 到 EL10 后 kubelet 起不来：`Failed to start ContainerManager … no PodsandBox found`
- 原因：一个 Dead 状态的 kube-proxy 容器（`--filter status=exited` 抓不到）。
- 状态：promoted → `k8s.sh fix` 自动删 Dead 容器

### 4.6 ★ 业务 Java pod 反复 OOMKilled
- 原因：镜像 JDK 8u201，启动参数 `-XX:MaxRAMPercentage=70`。cgroup v1 时能读到 2G limit → 堆 1.4G；EL10 只有 cgroup v2，8u201 读不到 → 按宿主机 61G 算 → 堆 43G。
- 处理：给 4 个业务 namespace 的 63 个工作负载注入 `JAVA_TOOL_OPTIONS=-XX:MaxRAM=$(limits.memory)`（downward API），镜像和命令不变。**CI 重新发布时要同步进发布模板**，长期是基础镜像升到 8u372+/11.0.16+/17+。
- 状态：promoted → `k8s.sh jvm-maxram`、`kubernetes.md`、`survey.sh` INFO

### 4.7 打补丁后 worker 全部 CPU 100%，大量 pod 起不来
- 原因：滚动更新（maxSurge=1/maxUnavailable=0）让约 60 个服务新旧 pod 同时启动；部分服务 liveness 只给 60 秒，而启动要 56~70 秒 → 被反复杀。
- 处理：旧 ReplicaSet 直接 `scale --replicas=0`；把一个 namespace 临时缩到 0，另一个起完再放回；几个启动慢的服务挪到空闲节点（临时 cordon 其它节点后删 pod）。没有修改任何探针配置。
- 状态：promoted → `kubernetes.md`

### 4.8 nfs-client-provisioner ImagePullBackOff
- 原因：`:latest` → `imagePullPolicy: Always`，quay.io 拉不到（节点上有镜像）。
- 处理：改 `IfNotPresent`，**同步改了业务方保存部署文件的目录里的 provisioner.yaml**（先备份）。

### 4.9 skywalking-oap（no-init 模式）起不来：`table: browser_error_log does not exist`
- 原因：no-init 模式启动时要求模板和**当天索引**都存在；很少有数据的表（browser_error_log、zipkin_span）当天索引不存在。升级前它连续跑了 133 天，从没重新检查过。
- 处理：重跑 init job 不够；按模板补建当天和次日的 `sw_*-YYYYMMDD` 索引后恢复。
- 状态：只留在报告（应用特例）；`kubernetes.md` 提示"长期运行的 pod 重启后可能暴露早已存在的问题"

### 4.10 wg-easy 重启循环：`iptables v1.8.3 (legacy): can't initialize iptables table 'nat'`
- 处理：`finalize.sh iptables-legacy`。状态：promoted → `finalize.sh`、`pitfalls.md` §7

### 4.11 worker2 宿主机业务
- 5 个手工启动的 Java 程序按升级前记录的命令行/目录/环境变量做成 systemd 服务（开机自启）。其中银行 B2C 外联客户端报"文件证书密码错误"，需要业务方重新输入证书密码，服务已建好但保持禁用。
- `LANG=zh_CN.GB18030` 需要 `glibc-langpack-zh`。
- 6 个 host 网络容器开机时比宿主机 nacos（启动约 4 分钟）先起来，注册失败后"运行中但没有端口"，nacos 就绪后 restart 恢复（与升级无关，任何重启都会这样）。
- mysql、nginx-vts-exporter 原来是 `restart=no`，改为 `unless-stopped` 并启动。
- 一个日志采集容器（vector，1G limit）追 11G 积压日志被 OOM，临时调到 2G；积压来自一个连不上外部 MQ 的服务疯狂打错误日志（外部服务拒绝连接，与升级无关）。
- 状态：promoted → `backup.sh` 记录手工进程 + `finalize.sh manual-procs`；`survey.sh` HIGH；`pitfalls.md`

### 4.12 worker3 redis → valkey、postfix
- EL10 没有 redis：valkey 已装但未启用、数据未迁移 → `finalize.sh redis-valkey`。
- IPv6 被禁用时 postfix `inet_protocols=all` 起不来 → ipv4。
- 状态：promoted → `finalize.sh`

### 4.13 一台 worker 监控反复报“出方向丢包”（升级后第 2~3 天）
- 阶段：升级后
- 现象：只有一台 worker 的 flannel.1 `tx_dropped` 大约每小时 +1（两天从 0 涨到 92），每次都触发夜莺丢包告警；业务无感知。
- 原因：6 台里只有这台的 `/etc/sysctl.conf` 没有 `net.ipv6.conf.*.disable_ipv6 = 1`。flannel.1 因此有 IPv6 link-local 地址，内核发出的 IPv6 组播（MLD/ND）在 VXLAN FDB 里没有对应条目，只能丢弃。抓包确认被丢的都是 IPv6 组播帧。
- 处理：和其它节点一样禁用 IPv6（postfix 同时改 `inet_protocols = ipv4`）；之后 1 小时 40 分钟、约 240 万个包 0 丢弃。
- 状态：promoted → `kubernetes.md` §4、`k8s.sh check`（flannel.1 有 IPv6 地址时提示）
